# 🎼 Pocket Orchestra v0.1

**Промпт → тематический музыкальный план → оркестровые партии → MusicXML + MIDI → прослушивание.**

Это **рабочий прототип**, а не готовый профессиональный симфонический композитор.
Его сильная сторона — редактируемые ноты, музыкальная форма, раздельные партии и воспроизводимость по seed. Финальное качество **обязательно проверяется на слух**.

## Три режима для первой композиции

Веб-пульт предлагает **«Только инструменты»**, **«Только голос»**, **«Инструменты + хор»**.

**Важно:** режимы с голосом в v0.1 пока являются только **нотным SATB-хором на Ahh/Ooh/Mmm**. Реальный русский сольный вокал, слова песни и раздельные аудиостемы ещё не реализованы; задача отслеживается в [GitHub issue #1](https://github.com/musikfed/muzikfed/issues/1).

**[Порядок обновления и первой композиции по всем трём сценариям](docs/FIRST_COMPOSITION.md)**. Сначала обновляем код, проверяем API и интерфейс; музыку запускаем отдельным шагом после этого. Уже установленный проект на CORE повторно клонировать не нужно.

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
bash scripts/check-core.sh
```

## Как проверить все режимы

**[Пошаговая проверка оркестра, квартета, SATB и объединённых составов](docs/TEST_MODES.md)** — через браузер и автоматически.

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
python3 scripts/smoke-core.py
```

Это создаст тестовые восьмитактовые задания через живой API и проверит пять составов, экспорты и черновой WAV оркестра. Режим LLM **не обязателен**: сначала тестируй с выключенной галочкой. Гласные хора в v0.1 — не полноценное русское пение.

## Возможности 0.1

- 12-партийный оркестр, 4-партийный струнный квартет, SATB-вокальный квартет, струнный квартет + SATB (8 партий), оркестр + хор (16 партий).
- Мотив A → A′ → B → A″, диатоническая гармония и каденция.
- Хоровой SATB: подбираются аккордовые обращения и плавность голосоведения; избегаются пересечения голосов и параллельные квинты/октавы на границах тактов.
- Слова промпта **без LLM** распознают несколько команд: вступление виолончелей, позднее вступление хора, тихая кода. Это ограниченный парсер, НЕ понимание произвольного текста.
- **Опциональная локальная LLM Ollama** предлагает прогрессии и мотив в проверяемом JSON. При недоступности LLM генерация продолжается автономно.
- MusicXML с динамикой, артикуляциями и слогами хора, Type-1 MIDI, JSON-отчёт проверок и отдельные файлы для хора/оркестра.
- Черновой WAV через FluidSynth, если установлен; качественный WAV через MuseScore Studio + бесплатные MuseSounds Core на .103.
- Веб-пульт с параметрами темпа, лада, тональности, плотности, экспрессии, напряжения, кульминации и инструментального состава.

## Распределение по твоей сети

- **CORE .100**, Ubuntu Server 24.04, RTX 3060: FastAPI, генерация нот, проверки, Ollama (опционально), FluidSynth.
- **GRAPHICS .103**, Windows 11 + RX 7600 XT: MuseScore Studio 4 + MuseSounds Core; качественная озвучка и экспорт.

### Запуск и обновление на Ubuntu CORE 192.168.0.100

**Основная папка — `/1tbdisk/muzikfed` на отдельном диске.** Исходники, виртуальное окружение, кэш uv и все результаты `outputs/` остаются в этой папке. Пользовательский systemd-unit находится в `~/.config/systemd/user/` по требованиям systemd.

**Проект уже клонирован и сервис запущен.** Для диагностики и обновления на Ubuntu CORE:

```bash
cd /1tbdisk/muzikfed
bash scripts/check-core.sh
# После публикации новых коммитов на GitHub:
bash scripts/update-core.sh
```

Веб-мордочка: **http://192.168.0.100:9095**. Если VPN маршрутизирует адрес CORE, Acer открывает её напрямую без SSH-туннеля. Прототип не имеет авторизации: **не публикуй порт 9095 в интернете**.

Первая установка на чистом диске, устранение `Permission denied`, работа с systemd, диагностика после обновления: **[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**. Как отправлять изменения через `git push`: **[docs/GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md)**.

### Локальный ИИ на CORE .100 (необязательно)

Поставь Ollama и нужную модель согласно официальной инструкции [ollama.com](https://ollama.com/). Пример:

```bash
ollama pull qwen3:8b
ollama run qwen3:8b
```

Запусти Pocket Orchestra; включи в веб-интерфейсе **«Использовать LLM»**. По умолчанию запрос идёт на `127.0.0.1:11434`. Для видеокарты 12 ГБ рекомендуется начинать с квантованной 8B, проверив драйвер NVIDIA и свободную VRAM. Дополнительных платных API не требуется.

### Получить финальное звучание на GRAPHICS .103

1. Установи [MuseScore Studio](https://musescore.org/) и через [MuseHub](https://www.musehub.com/) бесплатный **MuseSounds Core**, включая Muse Strings, Brass, Woodwinds, Percussion и Muse Choir.
2. Скопируй полученный `score.musicxml` на .103 (скачать через браузер, либо по VPN).
3. Открой MusicXML в MuseScore Studio. Проверь сопоставление инструментов, особенно **концертный строй валторны и кларнета**, а для струнного квартета — солирующие звуки вместо секций.
4. В микшере установи **MuseSounds** для нужных партий. Для хора проверь Ahh/Ooh/Mmm. При необходимости поправь нотацию, динамику и баланс. Сохрани родной `.mscz`.
5. Через File → Export сделай **WAV** (или FLAC). Это основной высококачественный результат. Возможно экспортировать PDF/партии для нот.

> Важное ограничение: `fluidsynth` **не воспроизводит MuseSounds**. MuseSounds работают только внутри MuseScore Studio. В v0.1 экспорт через MuseScore **ручной**, поскольку настройка библиотек и корректная пакетная автоматизация на Windows .103 пока не проверены на твоей машине.

### Добавить хор позже / раздельное сведение

Для состава «Оркестр + SATB хор» создаются отдельно `choir.musicxml`, `choir.mid`, `orchestra.musicxml`, `orchestra.mid`. Все начинаются на нулевом такте и имеют одинаковый BPM, так что партии можно позже отдельно озвучить, экспортировать и совместить в любой DAW или монтажной программе. Для «Струнный квартет + SATB» аналогично создаются `quartet.musicxml` и `quartet.mid` вместо файлов оркестра. **WAV-стемы** в v0.1 автоматически не рендерятся.

### Рендер без GUI на CORE .100

По умолчанию берётся SoundFont `/usr/share/sounds/sf2/FluidR3_GM.sf2` (пакет `fluid-soundfont-gm`). Если у тебя другой SoundFont:

```bash
export POCKET_ORCHESTRA_SF2=/path/to/your/soundfont.sf2
uv run pocket-orchestra
```

Для результатов используется `/1tbdisk/muzikfed/outputs/<uuid>` (файлы игнорируются Git). В `.gitignore` запрещена случайная публикация аудиосэмплов, библиотек и `.env`.

## Состав файлов

- `pocket_orchestra/composer.py` — мотив, развитие, партия/роль, распознавание основных сцен в промпте.
- `pocket_orchestra/harmony.py` — SATB, голосоведение, запрет параллельных совершенных интервалов на границах тактов.
- `pocket_orchestra/ollama.py` — опциональный локальный JSON-план LLM.
- `pocket_orchestra/export.py` — MusicXML, MIDI и вокальные слоги.
- `pocket_orchestra/quality.py` — технический анализ нот.
- `pocket_orchestra/app.py` — веб-API, рендер, безопасная раздача артефактов.
- `web/index.html` — отдельный интерактивный пульт без CDN.
- `tests/` — регрессионные тесты; `examples/` — пример партитуры, MIDI и отчёт.
- `docs/QUALITY.md` — ограничения и план качества.

## Чего пока нет (НЕ выдаётся за готовое)

- Генерации произвольной профессиональной формы из свободного текста без LLM;
- Реалистичного rubato по секундам, штрихов, дыхания и полноценного управления CC1/CC11;
- Глубокого контрапункта, оркестровочных правил для всех стилей, проверки аудио на слух;
- Автоматического сэмплерного рендера MuseSounds на .103 и удалённого сборщика WAV;
- Авторизации и многопользовательских очередей.

И главное: **5/5 или 7/7 автоматических проверок ≠ оценка музыки 10/10**. Это техническая корректность. Художественное качество требует прослушивания и сравнительных оценок.

## Как обновлять сервер и отправлять изменения на GitHub

**GitHub → CORE** (после коммитов, без повторного клонирования):

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
bash scripts/check-core.sh
```

**CORE → GitHub** (только если самостоятельно менял исходники):

```bash
cd /1tbdisk/muzikfed
git status
git add README.md
git diff --cached --check
git diff --cached
git commit -m "docs: update README"
git pull --rebase origin main
git push origin main
```

Вместо `README.md` выбирай реально изменённые файлы. Для `git push` настрой авторизацию GitHub. Перед коммитом **проверяй**, что в него не попадают сертификаты, `.env` или приватные ключи. Полные инструкции: [DEPLOYMENT.md](docs/DEPLOYMENT.md) и [GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md).

### Что пока нельзя обещать

Пять составов в текущем интерфейсе — это **нотные ансамбли**, а не три будущих аудиорежима. В частности, хор в v0.1 поёт только гласные (Ahh/Ooh/Mmm), полноценное исполнение русского текста в WAV ещё не реализовано. Движок для пения на русском, отделённые стемы и длинные песни — запланированные задачи v0.2+. Подробности в `docs/ROADMAP.md`.
