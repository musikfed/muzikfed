# Как проверять Pocket Orchestra: оркестр, хор, квартет и их сочетания

**CORE:** http://192.168.0.100:9095  
**Репозиторий:** `/1tbdisk/muzikfed` на Ubuntu 24.04.  
**Версия:** прототип v0.1 — нотная генерация и черновой WAV. Русский вокал со словами в этой версии **ещё не реализован**.

## Первый запуск через браузер (только оркестр)

1. С Acer открой `http://192.168.0.100:9095` через свой VPN.
2. Слева в **01 · Задание композитору → Состав** выбери **Симфонический оркестр**. На экране должны скрыться хоровые настройки.
3. В музыкальной форме оставь **16 тактов, D минор, 94 BPM**, seed **42**.
4. Ниже, в **03 · Оркестровщик и дирижёр**, **НЕ включай Ollama/LLM**. Оставь галочку **«Создать черновой WAV»**.
5. Нажми в самом низу левой панели **«✦ Сочинить и оркестровать»**. Жди появления **«Партитура готова»** справа.
6. Справа в **«Файлы произведения»** будут **MusicXML**, **MIDI**, **отчёт JSON**, а также аудиоплеер WAV (если FluidSynth сработал). Нажми Play, скачай MusicXML/MIDI.
7. В **«Инструментальные партии»** должно быть **12**, **ни одного голоса хора**.
8. Открой MusicXML на GRAPHICS .103 в MuseScore Studio + MuseSounds и сравни звучание с черновым FluidSynth.

**Важно:** до нажатия кнопки справа уже отображаются название, форма и цветные такты — это лишь превью настроек, **не готовая музыка**. Состояние `Ожидает генерации` означает, что пока ничего не создано.

## Все пять составов — вручную через браузер

Повторяй шаги выше, каждый раз меняя только **Состав** и, при необходимости, **Гласную хора** и **Вступление хора**. LLM поначалу выключена.

| Состав | Ожидаемых нотных партий | Файлы |
| --- | ---: | --- |
| **Симфонический оркестр** | 12 | `score.musicxml`, `score.mid` |
| **Струнный квартет** | 4 | `score.musicxml`, `score.mid` |
| **Вокальный квартет SATB** | 4 | `score.*` + `choir.musicxml`, `choir.mid` |
| **Оркестр + SATB** | 16 | `score.*` + раздельные `orchestra.*` и `choir.*` |
| **Квартет + SATB** | 8 | `score.*` + раздельные `quartet.*` и `choir.*` |

Кроме MusicXML/MIDI, все режимы формируют `report.json` и по запросу могут создать черновой `preview.wav`. В комбинированных режимах раздельные слои пока **только MIDI и MusicXML**, не WAV.

**SATB в v0.1 — это 4 нотные линии на Ahh/Ooh/Mmm, а не разборчивое пение русских слов.** Библиотеку реалистичного хора и русского певца внедрим отдельно. На CORE FluidSynth с GM SoundFont имитирует хор условным инструментальным тембром; не путай его с Muse Choir.

## Проверить все режимы одной командой на CORE

После обновления репозитория:

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
python3 scripts/smoke-core.py
```

`smoke-core.py` обращается к **реально запущенному API** на `192.168.0.100:9095`. Он создаёт по 8 тактов для каждого из пяти составов, проверяет, какие партии появились, открывает экспортированные MusicXML/MIDI, проверяет раздельные партии и **создаёт WAV для оркестра**. Сохраняет тестовые задания стандартным способом в `/1tbdisk/muzikfed/outputs/`. Проверяет работоспособность, а не художественную ценность музыки.

Режимы:

```bash
# Только API, партитуры, MIDI и JSON — без WAV:
python3 scripts/smoke-core.py --no-wav

# С WAV для всех пяти составов (выполнение дольше):
python3 scripts/smoke-core.py --wav-all

# Дополнительно проверить подключённую Ollama (модель qwen3:8b):
python3 scripts/smoke-core.py --llm
```

`--llm` сработает, только если **Ollama уже запущена** на CORE, а модель `qwen3:8b` локально загружена. Без этого обычный композитор продолжает работу, но тест `--llm` корректно сообщит о недоступности LLM.

Пример корректного вывода (иллюстрация, **не результат запуска на твоём CORE**):

```text
Health: OK, FluidSynth ready: True
[OK] Только оркестр: 12 part(s), ... WAV: yes
[OK] Струнный квартет: 4 part(s), ... WAV: no
[OK] Только SATB (гласные): 4 part(s), ... WAV: no
[OK] Оркестр + SATB: 16 part(s), ... WAV: no
[OK] Квартет + SATB: 8 part(s), ... WAV: no
Result: 5 passed, 0 failed
```

## Зачем переключатель «Использовать LLM»

Это опциональный музыкальный **планировщик**, а не обязательная часть звукового движка:

- **Выключено:** Python сам выбирает мотив, гармонию и распределяет партии. Самый простой воспроизводимый тест — одинаковые параметры и `seed=42`.
- **Включено:** приложение обращается к локальной Ollama на `127.0.0.1:11434`, просит модель `qwen3:8b` предложить **две гармонические последовательности по четыре такта и мотив**. Python валидирует JSON, а затем пишет реальные ноты и экспортирует MusicXML/MIDI.
- Если модель не установлена или недоступна, приложение возвращается к обычному композитору; в разделе результатов появится соответствующее сообщение.
- LLM не синтезирует голос и не делает FluidSynth более реалистичным. Качество оркестрового **звучания** зависит от сэмплов/артикуляции/микса; это проверяется отдельно в MuseScore на GRAPHICS .103.

Проверка Ollama на CORE (если хочешь её задействовать):

```bash
command -v ollama
ollama list
curl -fsS http://127.0.0.1:11434/api/tags
# Если Ollama работает, но модели ещё нет:
ollama pull qwen3:8b
```

Сначала протестируй без LLM, затем включи с теми же параметрами и сравни `report.json`, ноты и звук. Помни, что генерация LLM с температурой может меняться от запроса к запросу даже при одинаковом seed самого композитора.

## Если возникла ошибка

```bash
cd /1tbdisk/muzikfed
bash scripts/check-core.sh
systemctl --user status pocket-orchestra --no-pager
journalctl --user -u pocket-orchestra -n 100 --no-pager
curl -fsS http://192.168.0.100:9095/api/health
```

Если API готов, а WAV отсутствует, проверь текст под кнопкой генерации и наличие `fluidsynth` / `FluidR3_GM.sf2`. Если на Acer нет доступа к странице, проверь VPN-маршрутизацию и брандмауэр CORE; **не открывай TCP 9095 на внешний IP**, так как в v0.1 пока нет авторизации.

## Что проверять на слух

Пять режимов — это прежде всего **пять разных наборов нотных партий**, а не пять разных нейросетевых моделей. Отмечай, слышна ли мелодия, не заглушены ли струнные медными, внятна ли кульминация, интересна ли гармония и отличимы ли A, A′, B и A″. Технический отчёт не гарантирует хорошую музыку. Высококачественный WAV с MuseSounds на Windows .103 важнее чернового FluidSynth при оценке результата.
