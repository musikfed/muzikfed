# Pocket Orchestra: два ИИ-движка, три кнопки, одна RTX 3060

**Назначение:** создание законченных музыкальных произведений по **полному описанию** (не по заранее зашитым случайным фразам), с отдельной нотной партитурой, полноценной аудиопесней или гибридом. Цель — высокое качество; уровень Suno/Баха **не подтверждён**: он требует независимого прослушивания и экспертизы нот.

## Три понятные кнопки

| В веб-пульте | Движок | Результат |
| --- | --- | --- |
| **Создать партитуру MIDI / MusicXML** | Python (CPU) или на выбор **Qwen/Ollama — ИИ-полифонист** | Отдельные нотные партии, MIDI, MusicXML, WAV-проверка FluidSynth при желании |
| **Создать полноценную песню по промпту** | **ACE-Step 1.5** (CUDA на RTX 3060) | `neural_song.wav`, свой оригинальный звук и потенциально русский вокал; тексты могут быть указаны вручную или сгенерированы LM модели |
| **Гибрид: MIDI-аранжировка → нейросетевой WAV** | Последовательно: нотный движок → FluidSynth WAV → **ACE-Step cover** | Звук ACE-Step, полученный с учётом нотного аудио-ориентира; **не нотка-в-нотку** и без гарантий чистых отдельных голосовых стемов |

Каждая из двух аудиокнопок **всегда создаёт новое задание из текущих полей**. Старые произведения, настройки и файлы не переиспользуются по ошибке. Название, описание, лад, темп, стиль, слова песни и seed передаются в запрос. Смысловая интерпретация аудио генерируется моделью ACE-Step. Нотная запись Qwen отличается от аудиопартитуры ACE-Step — это **два разных авторских результата**, соединяемых звуком только через cover.

В поле **«Движок сочинения нот»** выбери обычный CPU-композитор или **«ИИ-полифонист Qwen»**. Второй вариант просит модель создать настоящие последовательности нот **двух независимых голосов** (сопрано/бас или скрипка/виолончель), проверяет формат и оставляет остальные оркестровые партии из нотного Python-композитора. Это начальная двухголосная полифония, а не автоматически доказанная художественная сложность фуг И. С. Баха.

## Как распределяем машину и видеопамять

```text
                  Acer Swift 3 (Win11, браузер, пульт)
                                  |
                          LAN / WireGuard VPN
                                  |
           .100 Huananzhi CORE, 2×Xeon, 48 ГБ, 2 ТБ
             +---------+--------------------------------+
             | Python нотный движок на CPU              |
             | Qwen3:8b через Ollama → AI-полифония     |
             | ACE-Step 1.5 → песни/аудио              |
             +---------+--------------------------------+
                                  |
                   готовые MusicXML / MIDI / WAV
                                  |
       .103 Windows GRAPHICS / Ardor AMD 5600 / RX 7600 XT 16GB
              MuseScore Studio + MuseSounds / DAW
              экспорт и ручной финальный монтаж
```

`.109` (входная группа, Docker, SSL) **не используется**; он не нужен для работы композитора. Не требуется пробрасывать порты `9095`, `11434`, `8001` на публичный IP; существующей LAN/VPN достаточно.

**VRAM не резервируется постоянно:**

1. При вызове ИИ-нотного композитора останавливаем отдельный сервис ACE-Step, если в данный момент нет нейрозадачи.
2. Ollama/Qwen создаёт реальные ноты/музыкальный план и текст, если это запрошено.
3. После ответа Ollama получает `keep_alive=0`: модель выгружается из GPU памяти.
4. При запросе аудиопесни `gpu_control` устанавливает эксклюзивную файловую аренду на одну задачу и просит Ollama освободить VRAM.
5. `pocket-orchestra-ace.service` запускается **только по требованию**, создаёт WAV, затем останавливается автоматически после его получения браузером.
6. Следующий нотный ИИ-запрос во время создания нейропесни вернёт сообщение «RTX занята», вместо параллельного запуска двух тяжёлых моделей.
7. После выключения CORE-сервиса вручную можешь остановить ACE отдельно командой `bash scripts/stop-ace-step.sh`.

Это **кооперативная защита между нашими приложениями**, не аппаратная блокировка GPU. Если другие программы используют RTX, расход VRAM может оставаться высоким. Даже если браузер закрыт, **серверный наблюдатель** проверяет задачу и после готового WAV останавливает ACE-Step; предусмотрен максимальный срок наблюдения 20 минут. При аварийном перезапуске основного Python-процесса наблюдатель теряется, поэтому пользовательская служба ACE-Step дополнительно ограничена системным временем работы (до 1 часа), а ручной `bash scripts/stop-ace-step.sh` остаётся способом немедленно освободить GPU. Состояние можно посмотреть через `GET /api/gpu/status`.

**Один GPU 12 ГБ не стоит одновременно делить на два крупных ИИ.** Для Qwen3:8b Ollama применяет подходящее сжатие; ACE-Step использует свой автонастройщик VRAM. Большая RAM и два Xeon позволяют переносить часть данных в память CPU, хотя скорость может падать.

## Как обновить CORE из GitHub и перезапустить

В SSH-терминале Ubuntu под `user`:

```bash
cd /1tbdisk/muzikfed

# Явное скачивание свежего кода с GitHub:
git pull --ff-only origin main

# Тесты, зависимости и перезапуск Pocket Orchestra:
bash scripts/install-core.sh

# Проверяем:
bash scripts/status-core.sh
git log -1 --oneline
curl -fsS http://192.168.0.100:9095/api/health
curl -fsS http://192.168.0.100:9095/api/gpu/status
```

Либо **короткая эквивалентная команда**:

```bash
cd /1tbdisk/muzikfed && bash scripts/update-core.sh
```

Этот скрипт уже содержит реальную команду `git pull --ff-only origin main`; не нужно делать оба варианта подряд. Открой на Acer `http://192.168.0.100:9095`, нажми **Ctrl+F5**.

## Как запустить два ИИ по требованию

**Qwen-полифонист**, если Ollama уже установлена на CORE:

```bash
ollama list
ollama pull qwen3:8b
```

Если Ollama не установлена, используй официальный способ её установки и проверь, что `curl http://127.0.0.1:11434/api/tags` отвечает. В интерфейсе выбери **«ИИ-полифонист Qwen»** и нажми **«Создать партитуру MIDI/MusicXML»**. Счётчик GPU может показывать загрузку, если модель работает на CUDA.

**ACE-Step** устанавливается **отдельно и только один раз** — она не скачивается обычным обновлением:

```bash
cd /1tbdisk/muzikfed
nvidia-smi
bash scripts/install-ace-step.sh
```

После этого в веб-пульте появятся активные кнопки песни и гибрида. Они сами запускают модель и после скачивания WAV останавливают её. Для диагностики:

```bash
journalctl --user -u pocket-orchestra-ace.service -n 80 --no-pager
nvidia-smi
curl -fsS http://192.168.0.100:9095/api/vocal/status
```

При первом запросе ACE-Step может скачивать веса, и запуск способен превысить ожидание веб-пульта; если это произошло, читай журнал, проверь свободное место, повтори запрос после загрузки модели. **Не публикуй порт 8001 в интернет** — сервер ACE-Step должен слушать localhost.

## Художественный контроль и реальное качество

- Сравнивай произведения на одинаковых условиях: новый промпт должен порождать узнаваемую смену образа и музыкального развития.
- Для ИИ-полифонии проверь нотную независимость голосов, интервалы, голосоведение, фразировку, секвенции, разрешения и гармоническое напряжение.
- Для ACE-Step слушай русский текст, дикцию, певческий тембр, контраст частей, отсутствие артефактов.
- Для гибрида сравни `score.mid`, опорный `preview.wav` и `neural_song.wav`. Если модель меняет мелодию, это не ошибка MIDI: `cover` допускает творческие изменения.
- Финальную работу по оркестровке, MuseSounds и сведению можно перенести на **GRAPHICS .103**. Пока автоматическая выгрузка WAV на .103 **не реализована**.
- Уровень коммерческих сервисов, естественный оперный голос или «качество Баха» нельзя подтвердить зелёными unit-тестами. Нужно настоящее испытание моделей на CORE и оценки по аудио.
