# Pocket Orchestra — включение и выключение CORE .100

**Проект:** `/1tbdisk/muzikfed`  
**Веб-пульт при запущенном сервисе:** http://192.168.0.100:9095  
**Служба:** `pocket-orchestra.service` — пользовательский systemd unit Ubuntu 24.04.

Управление ниже влияет **только на Pocket Orchestra**, не перезагружает Ubuntu, не отключает сеть/VPN, не останавливает Ollama, GPU, Docker, другие службы и не удаляет произведения в `outputs/`.

## Первый раз после обновления GitHub

На CORE .100 по SSH, обычным пользователем `user`:

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
bash scripts/status-core.sh
```

При обновлении установщик автоматически создаёт одноразово **сильный локальный код управления** в `.cache/admin-token` с правами владельца `0600` и сохраняет его между обновлениями. Код **не записывается в GitHub**, не выводится в логи и не публикуется в веб-интерфейсе.

Посмотреть свой код можно в SSH-терминале (не отправляй его в чат и не показывай никому):

```bash
cd /1tbdisk/muzikfed
bash scripts/show-control-token.sh
```

## Выключить через браузер

1. Открой на Acer по VPN `http://192.168.0.100:9095`.
2. Найди блок **«Управление CORE .100»**.
3. Введи локальный секретный код в поле «Код управления».
4. Нажми **«Остановить Pocket Orchestra и службу»** и подтверди.
5. Сервер поставит задание остановки с небольшой задержкой, чтобы браузер успел получить ответ; затем выполнит `systemctl --user disable --now pocket-orchestra.service`.

**Последствия:** веб-интерфейс на 9095 станет недоступен; служба не стартует сама при перезагрузке; файлы музыки, Git, виртуальное окружение и сертификаты остаются на месте.

**Почему нельзя включить обратно кнопкой на этой же странице?** Когда служба выключена, её веб-приложение также выключено — принимать команды некому. Для запуска используем SSH-скрипт ниже.

### Безопасность кнопки

Кнопка требует отдельный токен и подтверждение; API проверяет заголовок `Origin` и использует фиксированную команду без shell-инъекций. Не открывай порт 9095 на белый IP, пользуйся своим VPN. Потерянный токен можно заменить вручную при доступе к CORE, но никому не отправляй его. В v0.1 обычные эндпоинты генерации ещё **без общей аутентификации**.

## Команды start / stop / restart / status на CORE

Перейди по SSH на Ubuntu CORE (например, `ssh user@192.168.0.100`), выполни:

```bash
cd /1tbdisk/muzikfed

# Включить службу СЕЙЧАС и включить её автозапуск
bash scripts/start-core.sh

# Остановить службу СЕЙЧАС и отключить автозапуск
bash scripts/stop-core.sh

# Перезапустить (например, когда нужно обновить конфигурацию)
bash scripts/restart-core.sh

# Посмотреть статус
bash scripts/status-core.sh

# Последние 100 строк журнала
bash scripts/service-core.sh logs
```

Те же действия без обёрток:

```bash
systemctl --user enable --now pocket-orchestra.service
systemctl --user disable --now pocket-orchestra.service
systemctl --user restart pocket-orchestra.service
systemctl --user status pocket-orchestra.service --no-pager
```

Не запускай скрипты как root или через `sudo bash`; сервис принадлежит **обычному пользователю**.

Выполнить с Acer одной командой через SSH:

```powershell
ssh user@192.168.0.100 "bash /1tbdisk/muzikfed/scripts/start-core.sh"
ssh user@192.168.0.100 "bash /1tbdisk/muzikfed/scripts/stop-core.sh"
```

## Автозапуск после завершения SSH и после перезагрузки

`systemctl --user enable` включает пользовательскую службу, но для запуска без интерактивного входа в Ubuntu может потребоваться `linger`:

```bash
loginctl show-user "$USER" -p Linger
sudo loginctl enable-linger "$USER"
```

`stop-core.sh` делает `disable --now`, поэтому после выключения проекта даже включённый `linger` **не будет запускать его автоматически**. При следующем `start-core.sh` автозапуск снова включится.

## Обновление GitHub и остановленный сервис

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
```

Важно: `update-core.sh` вызывает `install-core.sh`, который **включает и запускает** сервис. Это ожидаемо для обновления и применяется даже если проект ранее был остановлен. Чтобы обновить код и снова остановить его, сразу используй `bash scripts/stop-core.sh`.

## План первых музыкальных проверок после обновления

Сначала проверим один и тот же музыкальный замысел в интерфейсе в трёх режимах:

| Режим | В v0.1 технически работает | Чего пока нет |
| --- | --- | --- |
| Только инструменты | Оркестр (12 партий) или квартет (4), нотная партитура, MIDI, FluidSynth WAV | Финальный автозвук MuseSounds |
| Только голос | SATB (4 нотные партии), гласные Ahh/Ooh/Mmm | Настоящий певец с русскими словами |
| Голос + оркестр / аранжировка | 12+4 или 4+4 партии, общий и раздельные MusicXML/MIDI | Настоящий русский вокал и изолированные WAV-стемы |

Слово «вокал» в текущем UI означает только **нотный хоровой эскиз**. Не выдавай его за живое русскоязычное пение. Реальные композиции создадим отдельно после проверки службы и сравнения вариантов.

Для подробной проверки см. [TEST_MODES.md](TEST_MODES.md).

## Диагностика

```bash
cd /1tbdisk/muzikfed
bash scripts/status-core.sh
bash scripts/check-core.sh
journalctl --user -u pocket-orchestra.service -n 100 --no-pager
```

`check-core.sh` предполагает, что служба должна работать, поэтому после намеренного выключения он сообщит, что API недоступен — это нормально. `status-core.sh` подходит и для включённой, и для выключенной службы.
