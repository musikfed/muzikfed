# Тест музыки и слов: почему повторялось, что делает GPU, как получить русский вокал

**CORE:** Ubuntu 24.04 Huananzhi X79, 2×Xeon, 48 ГБ RAM, RTX 3060 12GB.
**Веб-пульт:** http://192.168.0.100:9095 через существующий LAN/VPN.
**Каталог:** `/1tbdisk/muzikfed`. Музыка и результаты: `outputs/`.

## Итоги первых трёх реальных WAV (2 ноября 2026)

Пользователь подтвердил запуск генерации и прослушивание отдельных инструментальных и SATB примеров. Присланные файлы: ~51,53 с, ~45,10 с, ~51,52 с (44,1 кГц stereo). В старом алгоритме мелодии и гармонии выбирались из нескольких циклических четырёхтактных шаблонов, а имя/описание мало влияли на собственно ноты. Тесты 7/7 проверяли музыкальную *структуру*, а не выразительность. Мелодии звучали похожими; это реальная проблема творческого разнообразия, а не сбой оборудования.

## Что исправлено в нотном композиторе

- Используется **полный seed + заголовок + описание + стиль**, а не только `seed % 4` и `seed // 4 % 4`.
- Стало **12 заготовок мотивов** и более гибкие ритмы; контрастная фраза выбирается отдельно, мелкие вариации появляются по фразам.
- В интерфейсе появился переключатель характера: **Авто**, симфонический/кино, марш, лирика, народная мелодика, оперная фразировка, атмосферный.
- При одинаковых данных результат **детерминированный** (для сознательной повторяемости). Чтобы получить новые ноты, измени описание, название или seed либо нажми **«Новая вариация»**.
- **Важно:** это улучшение разнообразия, а не готовый генеративный композитор высокого класса. Гармония остаётся в рамках простых диатонических четырёхтактных схем; для действительно разных больших произведений нужен следующий этап.

## Настройки после обновления страницы

Веб-пульт сохраняет поля формы (включая описание, название, режим, состав, темп, seed, стиль, текст, галочки) в **localStorage браузера**. Через `Ctrl+F5` и обычную перезагрузку поля должны восстановиться. Они сохраняются только в браузере и не публикуются в GitHub. На другом браузере или устройстве эти настройки не появятся автоматически. Есть кнопка **«Сбросить сохранённые настройки»**.

## Русские слова песни — что уже есть

В режимах **«Только голос»** и **«Инструменты + хор»** появилось поле **«Текст песни»**.

1. Можно **вписать собственные русские стихи** (до 4000 символов).
2. Если оставить поле пустым, программа создаст **редактируемый шаблонный черновик**. Это пока не литературный ИИ.
3. Если доступна Ollama и включить галочку LLM, она попытается создать **оригинальный русский текст** по названию/описанию. При недоступности модели используется тот же шаблонный черновик с сообщением об этом.
4. После генерации доступен `lyrics.txt`; слова также **подставлены в нотные подписи партии сопрано в MusicXML** (по одному слову на ноту, без правильного слогоделения/фонетических ударений). Это подготовительный материал для вокального движка, а **не фактическое произнесение слов**.
5. Текущий `preview.wav` **НЕ поёт текст**. Это GM/SF2-демонстрация звуковых партий. Не выдаём синтезаторный хор за русского певца.

## Кто создаёт музыку и почему GPU 0%

- Ноты в стандартном режиме создаёт Python: `pocket_orchestra/composer.py`, работает на **CPU Xeon**.
- `pocket_orchestra/harmony.py` оптимизирует SATB на CPU.
- `pocket_orchestra/export.py` создаёт MIDI и MusicXML на CPU.
- `fluidsynth` читает MIDI и `FluidR3_GM.sf2` и рендерит **черновой WAV на CPU**.
- Если включить локальную **Ollama**, модель `qwen3:8b` может работать на RTX 3060 (если установлена и CUDA действительно активна), предлагая музыкальный план/текст песни. Но **не** синтезирует реальное пение и не создаёт WAV.
- Монитор GPU 0% в режиме без Ollama — **нормально**, это не ошибка видеокарты.

## Русский оперный певец и разные стили: следующий этап

Это **реализуемо**, но нужен отдельный синтезатор, модель и испытания на конкретной RTX 3060.

**Вариант A — целая песня по русскому тексту и стилю:** [ACE-Step 1.5](https://ace-step.github.io/ACE-Step-1.5/en/) — открытая модель генерации музыки, заявлены многоязычные тексты, множество жанров и невысокие требования к VRAM. Практический план: изолированное окружение на `/1tbdisk/muzikfed`, локальный генератор WAV, тесты дикции на русском и «оперный баритон/тенор/сопрано», затем интеграция трёх аудиорежимов в API. *Важное ограничение*: песня может не совпадать с нотами нашего Python-композитора; точный импорт MIDI/сведение нужно проверять отдельно. **API-мост ACE-Step 1.5 уже реализован в Pocket Orchestra** (постановка задачи, проверка статуса и скачивание отдельного `neural_song.wav`), но сама модель **ещё не установлена и не проверена на CORE**. [Установка и тест RTX 3060](ACE_STEP_SETUP.md). Реальная скорость и качество на RTX 3060 пока неизвестны.

Чтобы пробовать вариант A, сначала изучи [ACE_STEP_SETUP.md](ACE_STEP_SETUP.md), затем явно запусти отдельный сервис: `bash scripts/install-ace-step.sh` и `bash scripts/start-ace-step.sh`. Он не является частью обычного обновления проекта.

**Вариант B — спеть именно написанные ноты:** [OpenUtau](https://github.com/openutau/OpenUtau) + [DiffSinger](https://www.openutau.com/DiffSinger-support/) + **совместимый русскоязычный голосовой банк с разрешённой лицензией**. Требует подготовки слогов, ударений, совмещения фонем с нотами. Это точнее для партитуры, но более трудоёмко и качество сильно зависит от голосового банка.

Обе технологии требуют **пробного прослушивания** на русском языке. Не обещаем натуральное оперное звучание, разборчивую дикцию или отдельные качественные стемы до реального теста.

Смотри [GitHub issue #1](https://github.com/musikfed/muzikfed/issues/1) — полноценный русский вокал и раздельные `vocals.wav`, `instrumental.wav`, `mix.wav` будут отслеживаться там.

## Как обновить CORE из GitHub

В терминале Ubuntu .100 под обычным пользователем:

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
# Скрипт уже выполняет git pull --ff-only origin main, тесты и перезапуск.
bash scripts/status-core.sh
git log -1 --oneline
curl -fsS http://192.168.0.100:9095/api/health
```

В браузере Acer открой `http://192.168.0.100:9095`, `Ctrl+F5`. Проверь сохранение настроек, затем две совершенно разные темы при одинаковом seed, затем обнови страницу и убедись, что все поля на месте.

## Что оцениваем после обновления

Первое — **разнообразие**: два разных названия и описания должны давать разные мотивы и более заметную разницу ритмики, а не только другие инструменты.

Второе — **управляемость**: стили «марш» и «лирика» должны менять характер фраз, а свои слова должны сохраняться и попадать в `lyrics.txt`.

Третье — **реализм**: для оркестра сравни WAV FluidSynth с MuseScore Studio + MuseSounds на Windows GRAPHICS .103; для оперного голоса нужна отдельная будущая модель. Нотные проверки не являются оценкой качества звука.
