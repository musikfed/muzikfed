# Мониторинг Huananzhi CORE .100 (Xeon ×2, RAM, RTX 3060, VRAM)

Веб-пульт: **http://192.168.0.100:9095**. Монитор находится в верхней части правой панели и обновляется **раз в 3 секунды**. Данные получает с самого Ubuntu CORE по новому **`GET /api/metrics`**. Он только читает статистику и не изменяет настройки системы.

Монитор использует стандартный Linux `/proc`, сведения `/sys` о физических сокетах CPU и команду `nvidia-smi` (если драйвер NVIDIA уже установлен). Новые Python-пакеты и фоновые службы **не нужны**.

## Что показывает

| Показатель | Источник | Как читать |
| --- | --- | --- |
| **Xeon CPU в целом** | Разница счётчиков `/proc/stat` между опросами | Насколько заняты все логические потоки вместе |
| **CPU 1 / CPU 2** | `/sys/.../physical_package_id` + `/proc/stat` | Отдельная средняя загрузка каждого процессорного сокета |
| **Потоки и load** | `/proc/stat` и системная load average | Число видимых логических CPU; load — очередь задач, не проценты |
| **Оперативная память** | `/proc/meminfo`, `MemAvailable` | Занято из доступного объёма; файловый кэш Linux правильно учитывается |
| **RTX 3060 GPU** | `nvidia-smi` | Текущая общая загрузка GPU, температура и мощность |
| **VRAM** | `nvidia-smi` | Использовано / доступно MiB и процент, примерно 12 ГБ у RTX 3060 |
| **API-процесс** | `/proc/self/status` и учёт CPU процесса | RAM и нормализованная CPU-загрузка именно Python API |
| **Диск** | `shutil.disk_usage` | Занято на томе `/1tbdisk/muzikfed` |

**Первые 3 секунды CPU может быть «—»**, потому что загрузка вычисляется по разнице двух замеров. Это нормально. GPU 0% тоже может быть нормой.

**Не путай:** GPU/VRAM и CPU/RAM — **общесистемные** показатели. Если их нагружает Ollama или другая программа, монитор это покажет. API-процесс считается отдельно, но не включает отдельно запущенную Ollama и дочерний `fluidsynth`. Значение CPU API выражено в процентах **от всех логических потоков вместе**.

Видеокарта может показывать **GPU 0%, VRAM около нуля** при создании обычной партитуры: Python-композитор обычно работает на CPU, а FluidSynth тоже использует CPU. RTX будет использоваться при запуске GPU-вычислений (например, правильно настроенной Ollama). Если Ollama работает на CPU, монитор GPU может оставаться на нуле.

## Как обновить CORE из GitHub и перезапустить службу

В SSH на **Ubuntu .100** от пользователя `user`:

```bash
cd /1tbdisk/muzikfed
bash scripts/update-core.sh
bash scripts/restart-core.sh
bash scripts/status-core.sh
curl -fsS http://192.168.0.100:9095/api/metrics
```

`update-core.sh` **уже выполняет перезапуск** после обновления и тестов; `restart-core.sh` указан как дополнительная явная проверка. Если хочешь, можно его пропустить.

С Acer по SSH одной командой (PowerShell):

```powershell
ssh user@192.168.0.100 "cd /1tbdisk/muzikfed && bash scripts/update-core.sh && bash scripts/status-core.sh"
```

Открой на Acer **http://192.168.0.100:9095** и обнови страницу `Ctrl + F5`. Вверху правой колонки должна появиться панель **«Мониторинг Huananzhi CORE .100»**.

## Проверка NVIDIA

Если в интерфейсе написано `nvidia-smi не найден`, проверь в терминале CORE:

```bash
command -v nvidia-smi
nvidia-smi
nvidia-smi --query-gpu=name,utilization.gpu,memory.used,memory.total,temperature.gpu,power.draw --format=csv,noheader,nounits
```

Если `nvidia-smi` не работает, проверь драйвер NVIDIA в Ubuntu. Не переустанавливай драйвер вслепую — сначала изучи вывод. **Монитор не устанавливает драйверы, не запускает CUDA и не занимает VRAM ради проверки.**

Если драйвер исправен, но метрика по-прежнему недоступна, пришли текст ошибки без приватных сведений. Приложение ограничивает вызов `nvidia-smi` таймаутом 2,5 секунды и не ломает генерацию при отсутствии GPU.

## Как наблюдать реакцию компьютера

1. Открой страницу, запомни загрузку CPU/RAM/GPU/VRAM **в простое**.
2. Выбери **«Только инструменты → Симфонический оркестр»**, 16 тактов, без LLM и нажми генерацию. Смотри на CPU: Python-композитор и FluidSynth должны использовать CPU; при коротком задании пик легко пропустить между 3-секундными замерами.
3. Позже, при установленной Ollama, включи LLM и сравни: если модель и её слои находятся на RTX, должны увеличиться расход VRAM и/или загрузка GPU.
4. Сравни `report.json` и наличие WAV. Одни числа мониторинга не гарантируют, что музыкальная генерация успешна: для этого смотри результат и файлы.

## Если данные не меняются

```bash
systemctl --user status pocket-orchestra --no-pager
curl -fsS http://192.168.0.100:9095/api/health
curl -fsS http://192.168.0.100:9095/api/metrics
journalctl --user -u pocket-orchestra -n 60 --no-pager
```

Система должна вернуть JSON с разделами `cpu`, `ram`, `gpu`, `process`, `storage`. Если открывается старая версия HTML, обнови страницу `Ctrl + F5`.

У этой версии нет авторизации API: оставляй веб-порт `9095` только на своей LAN/VPN, без публичного проброса.
